# Changelog
All notable changes to this project will be documented in this file.

## [Unreleased]
- Laravel 11, 12 and 13 support added.
- PHPUnit 10, 11 and 12 support for tests; test methods now use `#[Test]` attributes alongside the `@test` annotations.
- Fixed PHP 8.4 implicit nullable parameter deprecations in `BaseRepository::paginate` and `CommandExceptionHandler::outputConsoleException`.
- Enabled the existing `make:repository` "class already exists" test, which was missing its `@test` annotation.
- Fixed `BaseRepository::restore` when given a primary key instead of a model instance (`onlyTrashed` was accessed as a property).
- Code style formatted to PSR-12 with Laravel Pint (`composer format` / `composer lint`).
- Replaced Travis CI with GitHub Actions (PHP 8.1 × Laravel 8/9/10 and PHP 8.2–8.4 × Laravel 11/12/13, plus a code style check).
- Fixed the inverted condition in `BaseRepository::getModelClass()`. With no `$modelClass` set it returned `null` (and threw a `TypeError` when no model was bound); it now returns the bound model's class, or `null` when no model is bound. **Behaviour change** for repositories that bind a soft-deleting model without setting `$modelClass` (repositories generated by `make:repository` set it and are not affected): `hasSoftDelete()` now returns `true`, `forceDelete()` now permanently deletes instead of soft-deleting, `restore()` now works instead of throwing "does not use soft delete feature", and `delete()` on a collection now takes the soft-delete path.
- Fixed the `ModelRepository` facade: its `model-repository` container key was never bound, so every `ModelRepository::` call failed. It is now bound to a new `RepositoryFactory`, so `ModelRepository::make(User::class)` (or a model instance) returns a ready-to-use `GenericRepository`.
- Changed the `$allowException` default of `RepositoryContract::find()` from `true` to `false` to match `BaseRepository::find()`. PHP always uses the implementing class's default, so calls behave as before.
- `make:repository` now returns an explicit exit code (`Command::SUCCESS` / `Command::FAILURE`) from `handle()` instead of `null` on success. The process exit code is unchanged.
